# Deviations

Every departure from `docs/spec.md`, numbered, with the reason. Any hand edit to code by the owner is logged here. Session 1.2 also logs the places where the adopted spec goes beyond or differs from `BUILD.md`, so that the owner sees each one.

The dependency was already added in session 1.1. | 1.2 |
| DEV-002 | `BUILD.md` names `pdftotext` as the third cross-check. The spec uses pypdf instead, as a development dependency used by the tests. | Owner decision of 15 Nov 2026. Reasons and measurements: spec section 12.2. The CI step that installed poppler is removed. | 1.2 |

| DEV-023 | Audit reads annotation text from the annotation, not from the page. | DEV-024 | Spec P6 (normalisation is idempotent) does not hold. `normalise` applies NFKC, then drops the soft hyphen and zero-width characters. The test is `xfail(strict)` with that example; a narrowed test (no dropped characters) passes. **Closed in 1.8** (review 1.7 F-01, issue 9): the review showed that a dropped character between a letter and its accent defeated REQ-013. `normalise` now drops those characters before NFKC and `normalise_with_map` skips them when it forms groups. The owner confirmed this choice on 21 Nov 2026. P6 holds and its xfail is removed. | The properties session changes tests only. Fixing needs a spec decision: drop before NFKC, or accept non-idempotence. Matching uses a single pass, so no requirement is broken today. | 1.6 |
| DEV-025 | Spec P8 (removing all extents leaves no match) does not hold for loose matches. `ab abc c` with term `abc` becomes `ab  c` after removal, which the loose rule matches. The test is `xfail(strict)` with that example; the first half of P8 (extents lie inside the text) passes. | A real redaction leaves a gap, and verification (V1, V2) may read the gap as white space and report a loose survivor. Needs a spec decision on whether removed text is read as a break. Not checked: what `apply` does on a PDF built this way. | 1.6 |
| DEV-026 | Spec P2 (any single changed IBAN character breaks the match) is narrowed to a change of the same class, digit for digit or letter for letter. `FI26YE0T2000000000` with one 0 changed to O still passes ISO 13616 and length, found by Hypothesis and checked with an independent computation. | The ISO 13616 check cannot detect every digit-for-letter swap. The matcher follows REQ-020 correctly; the property was too strong. A pinned test records the value. | 1.6 |
