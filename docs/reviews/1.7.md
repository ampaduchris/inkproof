## Findings

### F-01 · S1 Critical · must-fix · M3
- Requirement: REQ-013 (MUST); the claim in spec section 1.1
- Where: `src/inkproof/normalise.py:26` (`normalise_with_map`); `tests/test_properties.py::test_p6_normalise_idempotent` (strict xfail, DEV-024)
- Observed: a zero-width space, zero-width joiner or soft hyphen between a base letter and its combining accent stops the term from matching. `normalise_with_map` groups a base letter only with the combining marks that follow it directly. The dropped character ends the group, so the accent is normalised alone and never composes. On a one-page PDF whose text layer reads `Payee: Jose` + U+200B + U+0301 + ` Zqvara`, `apply` with the term `José Zqvara` exits 0, reports "clean", and the output still holds the name. `audit` on the same file exits 0. The suite stays green: the only test in this area is the strict xfail for P6. DEV-024 records the fault in `normalise` and says "Matching uses a single pass, so no requirement is broken today". The probe shows that a requirement is broken.
- Expected: REQ-013 says zero-width characters and soft hyphens are ignored, so the term matches. `apply` removes it or exits 1.
- Command: `uv run python -c "from inkproof.matcher import Matcher; from inkproof.terms import parse_terms; m = Matcher(parse_terms('José Zqvara\n'.encode()), []); print([len(m.find(t)) for t in ('to José Zqvara.', 'to Jose​́ Zqvara.', 'to Jose‍́ Zqvara.', 'to Jose­́ Zqvara.')])"`, then `inkproof apply` on the PDF described above (Helvetica with a ToUnicode map: byte 0x01 to U+200B, byte 0x02 to U+0301), run three times
- Output: `[1, 0, 0, 0]`; three runs: `inkproof: clean: 0 match(es) removed and not found again by any check.` with `exit 0`; output text `'Payee: Jose​́ Zqvara'`
- Suggested change: in `normalise_with_map`, drop the characters in `_DROP` before grouping, so that a base letter and its marks form one group across them. Drop them before NFKC in `normalise` as well, which also makes P6 hold. Add a REQ-013 test with the three cases above, and remove the P6 xfail. GATE: DEV-024 asks the owner to choose between "drop before NFKC" and "accept non-idempotence". This finding shows that the second choice leaves REQ-013 false.
- Issue: https://github.com/ampaduchris/inkproof/issues/9

### F-02 · S1 Critical · must-fix · untested path
- Requirement: REQ-089 and REQ-055 (MUST); REQ-001 with the claim in section 1.1
- Where: `src/inkproof/apply.py:356` and `:361` (`report_path`, `write`); `src/inkproof/audit.py` (`run_audit`, `emit`); `src/inkproof/cli.py:49` and `:84`

No test passes a report path equal to another path.

- Command: R1 from `PYTHONPATH=tests uv run python -m fixturegen <dir>` copied to `in.pdf`, then `uv run inkproof apply in.pdf --patterns email -o out.pdf --report in.pdf`; `uv run inkproof audit aud.pdf --patterns email --report aud.pdf`; `uv run inkproof apply in5.pdf --patterns email -o out5.pdf --report out5.pdf`

- Suggested change: resolve the report path and exit 2 when it equals `IN`, `OUT` or the audited file, before anything is read or written. Add tests tagged REQ-055, REQ-089 and REQ-006 for the three cases.
